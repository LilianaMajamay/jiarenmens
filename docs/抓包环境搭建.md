# 东方财富 APP 抓包环境搭建（获取新接口会话令牌）

实盘组合新接口（`spzhapi.dfcfs.cn`）的会话令牌（`SPZH_CT_TOKEN` / `SPZH_UT_TOKEN`）会过期，
过期后需要重新抓取。本文档记录完整抓包环境（Android 模拟器 + mitmproxy）的搭建与使用。

> 2026-08 验证有效。东方财富 APP 11.2.2（`com.eastmoney.android.berlin`）。

## 一、总体架构

```
MuMu 模拟器(Android 15, x86_64, root)
   │  东方财富 APP（arm64 原生库，靠 MuMu 的 ARM 转译运行）
   │  iptables DNAT 强制所有 80/443 → 10.0.2.2:8080
   ▼
mitmproxy（宿主 Windows，8080 端口，抓包插件 scripts/capture_api.py）
   ▼
logs/capture_flows.jsonl（完整请求/响应，含令牌）
```

APP 的核心 API 域名（`spzhapi.dfcfs.cn` 等）有 WAF（HTTP/2 + TLS 指纹校验），
PC 直连会被 `9081 "前方人数太多啦"` 拦截，所以必须让流量从模拟器经 mitmproxy 走。

## 二、一键下载工具

先运行准备脚本（下载 MuMu 安装包、东方财富 APK、frida-server，安装抓包依赖）：

```powershell
uv pip install -r scripts/requirements-capture.txt --python .venv\Scripts\python.exe
.venv\Scripts\python.exe scripts\setup_capture.py
```

产物在项目根目录 `tools/`：
- `mumu_installer.exe` — MuMu 6.x Windows 安装包（在线安装器，约 6MB）
- `dfcf.apk` — 东方财富 APK（约 147MB）
- `frida-server-*-android-x86_64.xz` — Frida（证书锁定绕过备用）

## 三、安装 MuMu 模拟器

1. **双击运行** `tools/mumu_installer.exe`（需要管理员权限，UAC 弹窗点"是"）
2. 按提示安装到默认位置（本项目装到 `D:\AndroidSDK\MuMuPlayer`）
3. 启动 MuMu，等待 Android 系统启动完成

> MuMu 自带 ARM 转译（`libnb`/native_bridge），可以运行 arm64-only 的东方财富 APP。
> 官方 AVD 模拟器跑不了该 APP（UnsatisfiedLinkError），雷电模拟器在本机因 Hyper-V 冲突无法启动。

## 四、连接与安装 APP

MuMu 的 adb 端口为 `127.0.0.1:16384`（同时监听 5555/7555）：

```powershell
$adb = "D:\AndroidSDK\platform-tools\adb.exe"   # 或 D:\AndroidSDK\MuMuPlayer\nx_main\adb.exe
$adb connect 127.0.0.1:16384
$adb -s 127.0.0.1:16384 root                     # MuMu 是 userdebug 镜像，可直接 root
$adb -s 127.0.0.1:16384 install -r tools\dfcf.apk
```

## 五、安装 mitmproxy 证书到系统证书库（关键！）

Android 15 的 APP 只信任系统证书（`/apex/com.android.conscrypt/cacerts`），
且 `adb shell` 每次命令都在独立 mount namespace 里 —— 必须用 `nsenter` 挂进 **zygote** 的命名空间，
并修正 SELinux 上下文，APP 才能读到证书。

```powershell
# 1. 首次启动 mitmproxy 生成 CA（证书在 %USERPROFILE%\.mitmproxy\mitmproxy-ca-cert.pem）
.venv\Scripts\mitmdump.exe -p 8080

# 2. 证书文件名 = subject_hash_old。mitmproxy 默认 CA 固定为 c8750f0d
#    （验证: openssl x509 -inform PEM -subject_hash_old -in mitmproxy-ca-cert.pem -noout）

# 3. 准备证书目录（含原厂 145 个证书 + mitmproxy 证书）
$adb -s 127.0.0.1:16384 shell "rm -rf /data/local/tmp/cacerts && mkdir -p /data/local/tmp/cacerts && cp /system/etc/security/cacerts/* /data/local/tmp/cacerts/"
$adb -s 127.0.0.1:16384 push "$env:USERPROFILE\.mitmproxy\mitmproxy-ca-cert.pem" /data/local/tmp/cacerts/c8750f0d.0
$adb -s 127.0.0.1:16384 shell "chmod 644 /data/local/tmp/cacerts/c8750f0d.0; chcon -R u:object_r:system_file:s0 /data/local/tmp/cacerts"

# 4. 挂进 zygote 命名空间（关键：nsenter -t <zygote_pid> -m）
#    zygote/zygote64 的 pid 用: adb shell pidof zygote / pidof zygote64
$adb -s 127.0.0.1:16384 shell "nsenter -t 659 -m -- mount --bind /data/local/tmp/cacerts /system/etc/security/cacerts"
$adb -s 127.0.0.1:16384 shell "nsenter -t 659 -m -- mount --bind /data/local/tmp/cacerts /apex/com.android.conscrypt/cacerts"
$adb -s 127.0.0.1:16384 shell "nsenter -t 660 -m -- mount --bind /data/local/tmp/cacerts /system/etc/security/cacerts"
$adb -s 127.0.0.1:16384 shell "nsenter -t 660 -m -- mount --bind /data/local/tmp/cacerts /apex/com.android.conscrypt/cacerts"
```

验证：重启 APP 后，`cat /proc/<app_pid>/mounts | grep cacerts` 应能看到
`/data/local/tmp/cacerts` 的绑定挂载；`ls /system/etc/security/cacerts/` 应为 146 个证书。

> 坑：只挂 `/system/etc/security/cacerts` 不够，Android 15 conscrypt 读的是 APEX 路径；
> 不修 SELinux 上下文会报 "Trust anchor for certification path not found"；
> 不挂进 zygote 命名空间则 APP 完全看不到证书。

## 六、强制代理（iptables DNAT）

APP 会绕过系统全局代理直连，需要用 iptables 把所有 80/443 流量 DNAT 到宿主机的 mitmproxy：

```powershell
$adb -s 127.0.0.1:16384 shell settings put global http_proxy :0
$adb -s 127.0.0.1:16384 shell "iptables -t nat -F OUTPUT"
$adb -s 127.0.0.1:16384 shell "iptables -t nat -A OUTPUT -p tcp --dport 443 -j DNAT --to-destination 10.0.2.2:8080"
$adb -s 127.0.0.1:16384 shell "iptables -t nat -A OUTPUT -p tcp --dport 80  -j DNAT --to-destination 10.0.2.2:8080"
```

（10.0.2.2 是 MuMu/VirtualBox NAT 中宿主机的别名；mitmproxy 必须监听 0.0.0.0:8080。）

## 七、启动抓包

```powershell
.venv\Scripts\mitmdump.exe -s scripts\capture_api.py -p 8080
```

插件会记录所有东方财富域名（`eastmoney.com` / `dfcfs.cn` / `18.cn` 等）的完整请求/响应到
`logs/capture_flows.jsonl`，TLS 握手失败记录在 `logs/capture_ssl.log`。

然后在 MuMu 窗口里操作 APP：打开"实盘组合"，点几个选手的详情/持仓/调仓，停留几秒。

## 八、提取令牌

在 `logs/capture_flows.jsonl` 中搜索 `spzhapi.dfcfs.cn` 的请求，URL/请求体里即可看到：

```text
ctToken=<你的ctToken>   utToken=<你的utToken>   userId=<你的userId>
deviceId=<你的deviceId>
```

把值填入项目根目录的 `.env`：

```dotenv
SPZH_CT_TOKEN=...
SPZH_UT_TOKEN=...
SPZH_USER_ID=...
SPZH_DEVICE_ID=...
```

> `.env` 已被 .gitignore 忽略，不会上传仓库。

## 九、Frida 备用方案（证书锁定绕过）

本次抓包通过"系统证书 + iptables"即成功，无需 Frida。若 APP 更新后加了证书锁定，
可尝试用 Frida 绕过（注意：东方财富有反调试，ptrace 附加会被 SIGKILL，需先注入
`scripts/frida_unpin.js` 中的 kill/tgkill 拦截，且只能 spawn 模式）：

```powershell
adb push tools\frida-server-*.xz /data/local/tmp/
adb shell "cd /data/local/tmp && xz -d frida-server-*.xz && chmod 755 frida-server-*"
adb shell "nohup /data/local/tmp/frida-server >/dev/null 2>&1 &"
.venv\Scripts\python.exe scripts\frida_run.py
```

## 十、常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| PC 直连接口返回 `9081 前方人数太多啦` | WAF 校验 TLS/HTTP 指纹 | 走模拟器 + mitmproxy，不要 PC 直连 |
| 证书装了但报 "Trust anchor not found" | SELinux 上下文错 / 挂错命名空间 | 重做第五节，`chcon system_file` + `nsenter -t <zygote>` |
| 抓不到 HTTPS 流量 | APP 绕过系统代理 | 用第六节 iptables DNAT |
| APP 闪退 `UnsatisfiedLinkError` | arm64 原生库在 x86 模拟器无法加载 | 必须用 MuMu（有 ARM 转译） |
| Frida 附加即被杀（signal 9） | APP 反调试检测 ptrace | spawn 模式 + 先注入 kill/tgkill 拦截脚本 |
